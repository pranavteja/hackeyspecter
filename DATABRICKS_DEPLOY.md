# Databricks Apps deployment

This app is configured to deploy on **Databricks Apps** with the included
`app.yaml` manifest.

## What `app.yaml` does

- **`command`**: launches Streamlit on the port Databricks injects
  (`$DATABRICKS_APP_PORT`) bound to all interfaces.
  The `DATABRICKS_APP_PORT` substitution is the only env-var expansion
  Databricks performs inside `command` (per the
  [Databricks app runtime docs](https://docs.databricks.com/aws/en/dev-tools/databricks-apps/app-runtime)).
- **`env`**: disables Streamlit's telemetry and sets a light theme so
  the app matches the in-code palette.

## Deploy

### Option A — Databricks CLI

```bash
# from the project root
databricks apps deploy hackey-specter --source .
```

### Option B — Databricks UI

1. In your workspace, go to **Apps** → **Create app**.
2. Choose **Custom app** (not a template) and point it at this folder.
3. The UI reads `app.yaml` and `requirements.txt` from the project root.

## Requirements file

Dependencies live in `requirements.txt` and are installed at build time:

```
streamlit>=1.31.0
streamlit-extras>=0.3.0
watchdog>=4.0.0
openai>=1.40.0
```

The app runs off the curated catalog in `data/content.py`. The
"Why you will love this" section is generated by OpenAI when a key is
present, and falls back to a deterministic rule-based explainer when
the key is absent — so the app works with or without the LLM.

## OpenAI API key (for the LLM "why" section)

The key is read from the `OPENAI_API_KEY` env var. On Databricks it is
injected via `app.yaml`'s `valueFrom`, which references a **registered
secret resource** (a legacy workspace secret scope — NOT a Unity
Catalog secret). Locally, `export OPENAI_API_KEY=sk-...` before running.

> **Important:** `valueFrom` takes a **resource key** (a label you
> assign when registering the secret as an app resource), NOT the
> scope/key path. See:
> https://docs.databricks.com/aws/en/dev-tools/databricks-apps/secrets

### Set up the secret (one-time)

You've already done steps 1–2:

```bash
# 1. Create the secret scope
databricks secrets create-scope llm-secrets

# 2. Put your OpenAI key in it
databricks secrets put-secret --scope llm-secrets --key openai_api_key
#    (or with --string-value as you did)
```

Now register the secret as an app resource (required before `valueFrom`
can resolve it):

**Via the Apps UI (simplest):**
1. Go to **Apps → your app → App resources → + Add resource → Secret**
2. Scope: `llm-secrets`
3. Key: `openai_api_key`
4. Permission: **Can read**
5. Resource key: `openai-key`  ← must match `valueFrom` in `app.yaml`
6. Click **Confirm**

**OR via `databricks.yml`** (if using Declarative Automation / bundles):
```yaml
resources:
  apps:
    hackey-specter:
      resources:
        - name: openai-key            # this IS the resource key
          secret:
            scope: llm-secrets
            key: openai_api_key
            permission: READ
```

### How `app.yaml` references it

```yaml
env:
  - name: OPENAI_API_KEY
    valueFrom: openai-key   # the resource key you assigned above
```

This is already wired in the repo's `app.yaml`. If you used a different
resource key when registering, update that line to match.

### Without a key

If `OPENAI_API_KEY` is absent (e.g. you deploy before registering the
resource), the app still runs — the "Why you will love this" boxes use
the rule-based explainer. No errors, just less lyrical copy.

### Verifying the key is wired

After deploy, open the app, go to **🔍 Mood First Search**, type a
feeling, and expand **"Why will I love this?"**. LLM-generated prose
(2-3 evocative sentences, no `**Title** by Creator (Year)...` prefix)
means the key is live. The rule-based prefix means the key didn't
reach the process — check the resource registration and that the
resource key matches `valueFrom: openai-key` in `app.yaml`.

## Verifying locally that the manifest is correct

```bash
# quick sanity check
python3 -c "import yaml; yaml.safe_load(open('app.yaml'))" && echo "app.yaml is valid YAML"

# simulate the command locally (substitute 8000 for DATABRICKS_APP_PORT)
DATABRICKS_APP_PORT=8000 streamlit run app.py \
  --server.port=$DATABRICKS_APP_PORT \
  --server.address=0.0.0.0 \
  --server.headless=true \
  --browser.gatherUsageStats=false
```

## Port handling

Streamlit's default is `8501`. Databricks Apps expects the process to
listen on `$DATABRICKS_APP_PORT` (typically `8000`). The `--server.port`
flag in the command line handles that automatically — no code change
needed.
